# Java 概念 → 可视化隐喻对照表

动画讲代码的核心不是"把代码贴上去念"，而是**用一组具体输入把方法跑一遍**，让观众看见状态怎么变。下面是常见 Java 结构对应的画法，按需取用。

## 目录
1. 通用骨架：代码 + 状态双栏
2. 控制流：分支、循环、递归
3. 数据结构：数组、链表、HashMap、树
4. 对象与内存：栈、堆、引用
5. 并发：线程、锁、volatile、线程池
6. Stream / Lambda / 集合管道
7. Spring / 框架类方法
8. 复杂度与边界情况

---

## 1. 通用骨架：代码 + 状态双栏

绝大多数方法都适用：左半区放代码（`java_code`），右半区放运行时状态，用黄框 `line_box` 标出当前行，右侧状态同步变化。

```python
code = java_code(SRC).move_to(LEFT_PANEL)
box = line_box(code, 0)
self.say(FadeIn(code), Create(box))
# 走到第 3 行，同时更新右侧变量
self.say(Transform(box, line_box(code, 2)), var_i.animate.become(cn("i = 1").move_to(var_i)))
```

- 代码超过 ~18 行时只截取核心片段，用 `// ...` 省略样板代码；行号用 `line_numbers_from` 对齐原文件更好。
- 变量面板用 `VGroup(cn("i = 0"), cn("sum = 0")).arrange(DOWN, aligned_edge=LEFT)`，更新值用 `Transform` 或 `become`。

## 2. 控制流

| 结构 | 画法 |
| :--- | :--- |
| `if/else` | 条件表达式放大显示 → 判真/假（绿 ✓ / 红 ✗）→ 黄框跳到对应分支 |
| `for/while` | 数组格子 + 指针箭头 `Arrow` 随 i 移动；只完整演示前 2~3 轮，其余用"快进"（缩短 run_time）并说明规律 |
| 递归 | 右侧画**调用栈**：每次调用压入一个矩形帧（方法名+参数），返回时弹出并把返回值飞回上一帧 |
| `try/catch/finally` | 异常用红色闪电/方块从抛出点沿调用栈向上"冒泡"，被 catch 截住处高亮 |
| `switch` | 一排 case 标签，匹配项高亮；JDK 14+ 箭头语法同理 |

## 3. 数据结构

- **数组 / ArrayList**：一排 `Square` + 下标；扩容时画新数组（1.5 倍）并逐个 `copy` 箭头搬运。
- **链表**：`RoundedRectangle` 节点 + `Arrow` 指针；插入/删除时先画新指针再断旧指针，讲清顺序。
- **HashMap**：竖排桶数组（table），key → `hash()` → 扰动 `h ^ (h >>> 16)` → `& (n-1)` 得到下标，用一条流水线逐步显示中间值（二进制可用 `cn("0b1010...")` 等宽显示）；冲突时桶后挂链表，链长 ≥ 8 且容量 ≥ 64 时变红黑树（换成树形布局）。
- **二叉树 / 红黑树**：节点 `Circle` + 连线，旋转用 `animate.move_to` 让节点移到新位置；红黑节点直接上色。
- **队列 / 栈**：横向或纵向格子，入队出队用位移动画。

## 4. 对象与内存

- 左侧"栈"（方法帧，局部变量），右侧"堆"（对象方块）。引用 = 从栈变量指向堆对象的箭头。
- `=` 赋值引用 → 箭头改指向；`new` → 堆中淡入新对象；失去所有引用 → 对象变灰（可被 GC）。
- 值传递 vs 引用传递、`String` 不可变、`==` vs `equals` 都用这个图讲最清楚。

## 5. 并发

- 每个线程一条横向**泳道**（不同颜色），时间从左到右；`synchronized`/`Lock` 画成一把锁图标，线程拿到锁时锁变成该线程的颜色，其他线程在锁前排队（`BLOCKED`）。
- `volatile` / 可见性：主内存 + 每个线程的工作内存副本，写操作刷回主内存的箭头。
- CAS：比较值（期望值 vs 实际值）并排显示，相等则替换，否则重试的循环箭头。
- 线程池：任务方块进入队列 → 核心线程取任务 → 队列满时创建非核心线程 → 再满触发拒绝策略。

## 6. Stream / Lambda

- 画成**流水线**：源集合 → `filter` 闸门 → `map` 变形机 → `collect` 收集桶。元素小方块逐个流过，被过滤的掉落变灰。
- 强调惰性：终端操作前元素不动，调用 `collect` 后才开始流动。

## 7. Spring / 框架类方法

- 用**时序图**风格：参与者（Controller、Service、代理对象、Repository、DB）竖排生命线，调用是横向箭头。
- AOP/事务：先画代理对象包住目标对象，调用先进代理（开启事务）→ 目标方法 → 代理（提交/回滚）。
- 源码太长时只讲主干路径，把分支列为"本视频不展开"。

## 8. 复杂度与边界情况

- 末节建议用 1~2 句讲时间/空间复杂度（可画 n 增长时操作次数的柱状图），再列出 1~3 个边界情况（空输入、null、越界、并发修改）并指出代码中处理它的那一行。
