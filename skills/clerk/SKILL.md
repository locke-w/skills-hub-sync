# Clerk - 工信部合规报告填写助手

## 概述

本技能用于自动化填写工信部APP隐私合规检测报告。核心工作流程：
1. 读取动态分析报告（.docx），提���API调用和SDK信息
2. 获取隐私政策内容（通过URL），提取已声明的信息
3. 对比动态报告与隐私政策，找出差异
4. 将结果填入工信部报告的对应表格中

## 前置要求

需要 `python-docx` 库来处理 .docx 文件。如果未安装，先执行：
```bash
pip3 install python-docx --break-system-packages
```

## 输入文件说明

用户需要提供以下文件：

### 1. 动态分析报告（可能有多个文件，内容可能相同）
- 文件命名规则：`{包名}-{UUID}_dynamic.docx`
- 关键表格结构（以表格索引为准，从0开始）：
  - **表格0**：样本信息（应用名、包名、版本等）
  - **表格1**：测试设备信息
  - **表格2**：任务信息
  - **表格3**：API调用频次（同意前），表头 `['API名称', '调用频次(同意前)']`
  - **表格4**：API调用频次（同意后），表头 `['API名称', '调用频次(同意后)']`
  - **表格5**：SDK调用（同意前），表头 `['SDK名称', 'API名称(同意前)']`
  - **表格6**：SDK调用（同意后），表头 `['SDK名称', 'API名称(同意后)']`

> 注意：多个动态报告文件内容可能相同，只需读取其中一个即可。

### 2. 隐私政��
- 通常是一个URL链接（如 `http://m.youshu.cc/pages/privacyProtocol/`）
- 需要通过 WebFetch 获取页面内容
- SDK列表可能是隐私政策页面中的一部分，也可能是一个单独的链接/附件

### 3. 工信部报告（待填写）
- 文件命名规则：`{应用名}-{版本号}-工信部{日期}.docx`
- 基于模板 `xxxapp-报告-工信部（新版式2025.10.10修订）.docx` 生成
- 关键表格结构（以表格索引为准，从0开始）：
  - **表格0**：应用详情
  - **表格1**：检测结果总表
  - **表格2**：2.1.1 违规收集个人信息
  - **表格3**：2.1.2 超范围收集个人信息
  - **表格4**：2.1.3 违规使用个人信息
  - 后续表格依次对应后续检测项

## 核心填写规则

### 规则1：2.1.1 违规收集个人信息 - 序号2（表格2，行4）

**位置**：工信部报告表格2，行4（序号2），"截图"列（第3列，索引2）

**内容来源**：动态报告 3.1节 API调用频次 - 表格4（同意后的API调用频次表）

**填写内容**：将动态报告表格4中所有API名称列出。格式为每行一个API名称。

**对比逻辑**：提取动态报告中所有被调用的API名称，对比隐私政策中是否有声明。如果隐私政策中没有声明某个API对应的个人信息收集行为，则该API需要被标注出来。

### 规则2：2.1.1 违规收集个人信息 - 序号3（表格2，行5）

**位置**：工信部报告表格2，行5（序号3），"截图"列（第3列，索引2）

**内容来源**：动态报告 3.2节 SDK调用 - 表格6（同意后的SDK调用表）

**填写内容**：将动态报告表格6中的SDK信息列出。需要与隐私政策做对比——隐私政策中未声明的SDK及其收集的个人信息，需要写入此处。

**对比逻辑**：
1. 从动态报告表格6提取所有SDK名称和对应的API调用
2. 从隐私政策中提取已声明的SDK列表
3. 找出动态报告中存在但隐私政策中未声明的SDK
4. 对于已声明的SDK，找出其收集了隐私政策未声明的个人信息类型
5. 将差异信息写入截图列

### 规则3：2.1.2 超范围收集个人信息 - 序号2（表格3，行4）

**位置**：工信部报告表格3，行4（序号2），"截图"列（第3列，索引2）

**内容来源**：动态报告 3.1节 API调用频次 - 表格4（同意后的API调用频次表）

**填写内容**：从动态报告表格4中提取API调用信息，需要做以下处理：
1. **删除**总调用频次为1次或2次的条目（低频调用不视为超范围）
2. **高亮**（黄色标记）总调用频次超过10次的条目
3. 格式为每行一个API名称及其频次信息

**频次计算**：每个API名称对应的调用频次列中，包含多个SDK的调用次数，需要将同一API下所有SDK的调用次数加总作为总频次。

## 执行步骤

### Step 1: 读取动态分析报告
使用 python-docx 读取动态报告的 .docx 文件，提取：
- 表格4（API调用频次-同意后）的所有行
- 表格6（SDK调用-同意后）的所有行

```python
from docx import Document

doc = Document('动态报告路径.docx')
# 表格4：API调用频次(同意后)
api_table = doc.tables[4]
# 表格6：SDK调用(同意后)
sdk_table = doc.tables[6]
```

### Step 2: 获取隐私政策
使用 WebFetch 获取隐私政策URL的内容，提取：
- 隐私政策中声明的个人信息收集类型
- 隐私政策中声明的第三方SDK列表
- SDK各自声明收集的信息类型

如果页面内容为空（可能是动态加载的SPA页面），告知用户需要手动提供隐私政策文本内容。

### Step 3: 对比分析
- 对比API：动态报告中的API vs 隐私政策声明的信息收集
- 对比SDK：动态报告中的SDK vs 隐私政策声明的SDK列表
- 标记差异项

### Step 4: 填写工信部报告
使用 python-docx 修改工信部报告的 .docx 文件：

```python
from docx import Document

report = Document('工信部报告路径.docx')

# 2.1.1 违规收集个人信息表格（表格索引2）
table_211 = report.tables[2]

# 序号2的截图列 - 填入API信息
table_211.rows[4].cells[2].text = api_content

# 序号3的截图列 - 填入SDK信息
table_211.rows[5].cells[2].text = sdk_content

# 2.1.2 超范围收集个人信息表格（表格索引3）
table_212 = report.tables[3]

# 序号2的截图列 - 填入超频次API信息
table_212.rows[4].cells[2].text = freq_api_content

report.save('输出路径.docx')
```

### Step 5: 黄色高亮处理
对于2.1.2中超过10次的条目，需要用黄色高亮标记：

```python
from docx.oxml.ns import qn
from docx.shared import RGBColor

# 对需要高亮的文本设置黄色背景
run = paragraph.add_run(text)
rPr = run._element.get_or_add_rPr()
highlight = rPr.makeelement(qn('w:highlight'), {qn('w:val'): 'yellow'})
rPr.append(highlight)
```

## 注意事项

1. **表格索引可能有偏差**：不同报告的表格索引可能不同，应该通过表头内容来定位正确的表格，而不是硬编码索引号。定位方法：
   - 找包含"违规收集个人信息"的表格 → 2.1.1
   - 找包含"超范围收集个人信息"的表格 → 2.1.2
   - 动态报告中找表头为 `['API名称', '调用频次(同意后)']` 的表格
   - 动态报告中找表头为 `['SDK名称', 'API名称(同意后)']` 的表格

2. **SDK名称格式**：动态报告中SDK名称格式为 `包名(中文名称)`，如 `com.getui.gtc(个推基础库)`。在填写和对比时需注意同一SDK可能有不同的表述方式。

3. **频次解析**：调用频次列的格式为多行文本，每行格式为 `SDK包名(SDK中文名, 调用N次)`。需要解析出每个SDK的调用次数，然后加总得到该API的总调用频次。

4. **输出文件**：修改后的报告应保存为新文件，不覆盖原文件。建议命名为 `{原文件名}_filled.docx`。

5. **隐私政策获取失败的处理**：如果隐私政策URL无法获取内容（动态加载页面），应提示用户手动提供隐私政策文本，或者尝试在URL后加参数触发服务端渲染。

## 使用示例

用户可能这样使用：

```
帮我填写工信部报告。
动态报告：/Users/xxx/Downloads/com.example.app-xxx_dynamic.docx
工信部报告：/Users/xxx/Downloads/某某app-1.0.0-工信部20260616.docx
隐私政策：http://example.com/privacy
```

或者更简单的：

```
填报告，文件都在 /Users/xxx/Downloads/ 下面
```

此时应该自动在指定目录查找匹配的动态报告和工信部报告文件。
