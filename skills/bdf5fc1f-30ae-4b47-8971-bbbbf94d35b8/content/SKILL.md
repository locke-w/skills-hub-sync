# 想法阶段验证（结构化魔鬼代言人）

把一个模糊想法，推到「不是在赌直觉，而是在对着证据下注」。方法来自 Anthropic「AI 创业生命周期 · 想法阶段」，核心用法是让 Claude 当**结构化的魔鬼代言人**。

## 何时用

用户带着一个还没被验证的产品/创业想法来——「我想做一个 X」「这个值不值得做」「帮我看看这个点子」——就用它。越早期越要狠。

## 贯穿所有步骤的五条原则

1. **问题 ≠ 方案。** 先把「问题」钉死，方案可以反复变、问题不该跟着变。一个常见失败模式：攻击想法时把**方案**打翻了，于是方案换了三次，却始终没有一句固定的问题假设可以指着。
2. **做魔鬼代言人，不捧场。** 主动找最强的反方论据和反证，而不是帮用户把想法说圆。当用户的推理真的让假设变强时，诚实承认「这几条反对被你干掉了」，然后立刻给出更狠的新反方。求真，不是为批评而批评。
3. **成功 = 真实用户行为**（注册 / 付费 / 转介），不是同行点赞。**当心回音壁**：用户给「同行内容」点赞，往往只是同行刷同行，不算数。也要警惕——你搜集证据的人群本身可能就是错的人群。
4. **桌面研究 + 自我辩论无法证伪你**，只能磨锋利你自己的先验。你控制的魔鬼代言人不会对你说「不」。所以每一条结论都要标上「**待真人验证**」，直到一个真实的目标用户证实或推翻它。

5. **每个检查点 = 说人话 + 停下来让用户拍板（一道可以提前收手的闸门）。** 在每个步骤的收尾检查点（**1c、1e、2e、3c、4c 之后**）各停一次。先给一段**大白话小结**：先甩最重要的那句结论；不用术语（非用不可就当场翻译）；老实讲哪些是确定的、哪些还是猜的；能一句话概括就先给那一句。**然后停住，绝不自动跑下一步**——把「继续 / 换方向 / 就此打住」明确交给用户决定。关键：每个检查点都是一道**止损闸门**——如果这里已经看出不是高价值机会，**就该停，这是成功不是失败**，省下后面整轮的力气。别因为流程还有后续步骤，就惯性地往下做。

## 步骤总览

1. **定义并压力测试问题假设**（已写）
2. **市场研究 + 竞品分层地图**（已写）
3. **设计客户访谈**（已写）
4. **设计方案概念**（已写）
5. ~~搭轻量原型~~ —— **不纳入本 skill**（造原型那步留给真正动手时再说）

**重要——这不是一次性动作**：问题假设一旦演变（尤其方案换形态），第 2 步必须**重跑**。最常见的失败是拿着为旧假设画的竞品图、估的市场，去指导一个已经变了的想法。

## 开始前：装好 opencli（「找反证」那步要用）

这套方法里「找反证 / 调研」靠 **opencli**——它把任意网站变成命令行，用来批量抓 HackerNews / Reddit / 小红书 / 知乎 / X 上的**真实用户抱怨和竞品评价**。没有它，1d 那步会退回「自己跟自己辩论」，整套方法最值钱的一环就废了。所以**一上来就检查 / 装好，并告诉用户这是前置条件**：

```bash
opencli doctor                         # 命令不存在(command not found)就先装 ↓
npm install -g @jackwener/opencli      # 需 Node ≥ 21；装完再 opencli doctor
```

两类站点要求不同，**开工前先跟用户讲清**：
- **PUBLIC（免登录）**：如 HackerNews，装完直接能跑。
- **COOKIE（需登录）**：Reddit / 小红书 / 知乎 / X——要本地 Chrome 登录目标站 + 装 OpenCLI 浏览器扩展，`opencli doctor` 要显示扩展已连接。若本地扩展连不上，就把这些命令拿到一个已登录的远端环境去跑（PUBLIC 的 HN 仍可本地跑）。
- **沙箱**：opencli 要走网络，常被沙箱拦（permission denied / fetch failed / TLS 断开）。被拦就在**关掉沙箱**的前提下跑这些命令（Claude Code 里用 Bash 的 `dangerouslyDisableSandbox`）——实测开了就通。

完整用法见 `opencli-usage` skill；想知道某站点有哪些命令，跑 `opencli list -f json`，别背命令清单（它会变）。

# 第 1 步：定义并压力测试问题假设

**目标**：把模糊想法打磨成一句**可证伪**的问题假设。

**这一步结束时，必须产出三样东西**：
- 一句可证伪的问题假设
- 拆开后的 4+1 个要素（其中「因为」是最危险的）
- 一份「承重假设 + 待真人验证清单」，直接交给第 3 步客户访谈

## 1a · 先把问题和方案分开

先只谈**问题**，把方案放一边。原因：方案是用来解决问题的手段，会随着认知不断换；如果问题定义里掺进了方案，方案一动，你就失去了衡量一切的那把尺。先问清楚——**谁有这个问题、多频繁、多严重、现在怎么凑合解决**——再谈任何解法。

## 1b · 把问题冻成一句可证伪的话

用这个格式：

> **[谁] + [可观测症状] + [频率/严重性] + 因为 [根因]**

唯一的判据：**一个真实的目标用户，能用一次对话证实或推翻它吗？** 不能，就还不够。

- ❌ 不可测：「合同审查太慢了。」（谁？多慢？为什么慢？无法证伪）
- ✅ 可测：「中型公司的法务团队，每个合同审查周期要花 3 天以上，因为修订意见散落在邮件里、而不是一份带版本管理的文档。」

**先冻结，再攻击。** 不要边攻击边改问题——攻击会一次次把方案打翻，但如果问题假设没有先被冻住，每一轮攻击只是在移动靶子，看起来很热闹，其实没有收敛。先有一句固定的、可证伪的问题假设，**然后**才开始找反证。

## 1c · 拆成 5 个要素

把那句话拆开，逐项填实：

| 要素 | 要点 |
|---|---|
| **谁（WHO）** | 越窄越好。挑一个最窄的试点人群（beachhead），而不是「所有 X」。 |
| **可观测症状** | 一个能被访谈或数据**证实或推翻**的现象，不是感受。 |
| **严重性 / 频率** | **诚实标注**：这是一个验证过的群体数字，还是只是二手轶事 / n=1？把「听说很多人这样」和「我自己就这样」当成假设，不是证据。 |
| **现在怎么应对** | 今天他们用什么凑合？这条最能暴露需求的真实强度——没有替代行为的「痛」，往往是假痛。 |
| **那个「因为」= 根因** | 见下，最危险。 |

**给每一个要素都贴上「已知」或「假设」的标签**，不只是严重性那一条。任何你答不出确切来源的格子，默认就是「假设」。一个被诚实标成「假设」的要素，本身就是一条「待真人验证」清单项——这样到了 1e 收尾时，待验证清单几乎是自动浮现的。把「听说很多人这样」「我拍脑袋觉得每天一次」当成假设，不要当事实。

### 关于「因为」（根因）—— 这一步最容易出错

根因常常**不止一个，而且互斥**。不要急着选一个，把所有候选根因都列出来，标注现有证据偏向哪个——**这正是客户访谈要去裁决的东西**。过早押错根因，是后面方案做错的总根源。

写法：

- **根因 A**：…（现有证据：偏向 / 不偏向，来自哪里）
- **根因 B**：…（现有证据：偏向 / 不偏向）
- → 哪个是真正的瓶颈，目前无人裁决 → 列为访谈头号问题

## → 1c 之后 · 先跟用户说人话（必做）

到这里**停一下，别急着跑调研**。用大白话跟用户讲清三件事，请他确认或纠正：
1. **我们现在认为你的问题是啥**——把 1b 那句冻结假设翻成口语，不带术语。
2. **我们替你猜了什么、多大把握**——尤其严重性那条，老实说「这个数字是我们拍的，还没验证」。
3. **最大的不确定是啥**——通常就是「因为」那几个互斥根因：「你这事到底卡在 X 还是 Y，现在没人知道，这正是接下来要查的。」

为什么停在这：花力气调研之前，先确认问题框对了。用户此刻纠偏，比后面推倒重来便宜十倍。

**然后停住，别自动跑 1d 调研。** 给用户三选一，等他拍板再走：
- ✅ 问题框对了 → 继续跑调研（1d）
- ✏️ 框歪了 → 回 1b 改完再走
- 🛑 已经看出不值得做 → **就此打住，省下整轮调研**

## 1d · 冻结之后，去「捞」反证（不是凭空反驳）

最关键的认知：**「找反证」不是让 Claude 凭空跟你对辩**——那只是同一个脑子在磨你自己的先验，再聪明也证伪不了你。真正扎实的反证，是**去你的用户和竞品真实说话的地方，把反对的声音捞出来**。这就是这一步要用 opencli 的原因。

证据分三档，别混：
1. **armchair 自我推理**（最弱）：你和 Claude 在脑子里辩。磨先验可以，证伪不行。
2. **opencli 抓来的真实群体声音**（强）：HN/Reddit/小红书/知乎/X 上成百上千条真人原话——竞品差评、用户自己描述的痛。**这一步的目标就是做到这一档。**
3. **1:1 真人访谈**（最强）：Step 3 才做。

⚠️ 第 2 档已经远强于第 1 档，但它**仍是二手桌面数据**，不是有人当面对你说「不」。它的作用是让你**带着弹药、带着该问的问题去访谈**，不是替代访谈。（我们上一轮正是栽在这：opencli 调研做得很扎实，却误以为已经"验证"过了。）

### 怎么捞（两路并行）

把 1c 里的「谁」和这个想法的竞品，翻译成搜索词，两路一起搜：
- **A 路 · 竞品差评**：现有方案 / 竞品的真实不满——他们没解决的痛，就是你的缝。
- **B 路 · 用户原话**：目标用户用自己的话描述这个问题时，到底说什么。

中文搜 小红书 / 知乎 / 即刻；英文搜 HackerNews / Reddit / X。命令形态（一律加 `-f json`）：

```bash
# PUBLIC（免登录，直接跑）
opencli hackernews search "<痛点关键词>" --limit 30 -f json
opencli hackernews read <thread-id> --limit 100 -f json        # 钻评论

# COOKIE（需登录 Chrome + 扩展，或在已登录的远端环境跑）
opencli reddit search "<竞品名 OR 痛点>" --subreddit <sub> --sort top --time year --limit 25 -f json
opencli xiaohongshu search "<竞品/痛点 没效果 踩坑>" --limit 20 -f json
opencli zhihu search "<痛点 怎么办 / 靠谱吗>" --limit 15 -f json
opencli twitter search "<竞品 lang:en min_faves:10>" --filter top --limit 30 -f json
```

### 捞回来怎么用

1. **按互动量排序**（赞 / 评论数），优先钻头部帖子的评论——信号最密。
2. **频率扫描**：用户描述这个问题时高频用什么词？**这些词命中你 1b 假设里的语言了吗？** 命中 = 问题-方案契合的正面信号；完全不命中 = 你可能在用一套用户根本没有的框架思考（这本身就是一条强反证）。
3. **归成四类反证**，每条注明来自哪条真实数据：
   - 负面市场信号（被做烂了？品类词被污染了？）
   - 失败竞品 / 死掉的渠道
   - 客户行为模式（嘴上要、行为上却不做 / 不付费？）
   - 结构性障碍（需要的人 ≠ 付钱的人？冷启动死循环？）
4. 每条结论标注它**支持还是反对**你的假设，以及**还差哪个真人来最终拍板**——这些「差一个真人」的点，直接进 1e 的待验证清单。

## 1e · 收尾交接

这一步结束，输出：

- ✅ **冻结的问题假设**（那一句）
- ⚠️ **承重假设清单**：哪些「必须为真、但还没被任何真人验证」的假设，撑着整个想法
- 🎯 **访谈头号必答问题**：一个真实目标用户最该先回答的那个问题（通常就是裁决根因 A/B、或验证付费意愿）

把这三样交给第 2、3 步。

## → 1e 之后 · Step 1 收尾，再跟用户说人话

Step 1 走完，给用户一段大白话总结（这次基于真实调研，比 1c 那次更有底）：
1. **你这问题是真是假**——我们查了真人怎么说，结论是……（真问题／伪问题／真但你押错了形态）。
2. **最该担心的两三件事**——把承重假设翻成人话，比如「会需要它的人，恰恰是最不愿掏钱的人」。
3. **下一步干嘛**——拿哪个问题、去问哪种真人；并讲清「现在这些都还是查来的、不是真人当面说的，所以下一步必须去聊」。

一句话概括最好：「**这问题是真的，但 ___ 这点很可能让它做不成，得先找 5 个真人确认。**」

**然后停住，别自动进 Step 2。** 给用户三选一，等他拍板：
- ✅ 值得继续 → 进 Step 2 市场调研
- ✏️ 该换形态 / 换人群 → 回 Step 1 重做
- 🛑 基本判死 → **就此打住**——Step 1 就看出做不成、在这里收手，是成功不是失败，省下市场调研和后面所有投入。

## 完整示例（真实案例，浓缩）

**模糊起点**：「我想做个 app，帮 vibecoder 生成病毒式的产品宣传视频。」

**1a 分离**：病毒传播是*结果*不是输入，先放下「生成视频」这个方案，只问问题。

**1b 冻结成一句**：
> 面向 C 端大众的独立开发者（尤其中国出海个人开发者），产品上线后普遍拿不到真实终端用户——多数发布在第一个月只有个位数注册；因为 [根因待裁决]。

**1c 五要素**：
- 谁：无受众、无预算的独立开发者；最窄试点 = 中国出海个人开发者
- 可观测症状：上线后真实用户 ≈ 0，宣传只触达同行（「开发者回音壁」）
- 严重性/频率：⚠️ 目前**只有二手轶事**（「97% PH 发布已死」「18 次浏览」）+ 自家产品 n=1，**没有验证过的群体数字**
- 现在怎么应对：发 HN/Reddit/PH launch、读免费 playbook、试 SEO/冷启动，然后放弃或撞运气
- 根因（互斥两版）：
  - **A 渠道**：不知道用户聚在哪 → 把内容喷进了没有用户的开发者空间。（桌面数据偏向 A）
  - **B 内容**：用户其实就在 TikTok/小红书，但开发者做不出能被算法推、被看完的内容。（创始人押 B，仅在算法平台成立）

**1d 攻击**发现：两个品类名（UGC / 代运营）都被污染成「廉价假货 / 割韭菜」；需要它的人（独立开发者，0 预算 DIY）≠ 付钱的人（电商/品牌）——结构性障碍。全部标「待真人验证」。

**1e 交接**：
- 承重假设：①付费意愿（0 预算人群真会付吗）②根因是 A 还是 B ③就算告诉他在哪发，他做得出吗（判断≠执行）
- 访谈头号问题：找**做 C 端产品**的开发者，问上次发布失败——到底是「我不会发内容」还是「其实没人要我的东西」。

# 第 2 步：市场研究 + 竞品分层地图

**目标**：搞清楚你冲进的是一个什么样的市场、谁已经在里面、以及有没有一个**付得起钱、又足够大**的人群。

**前提**：先有第 1 步冻结的问题假设。**问题假设一变，这一步全部作废、必须重做。**

产出四样：竞品 4 层图（含「它凭什么赢你」）+ top 未解决抱怨 + TAM/SAM/SOM 粗估 + 买家地图（谁掏钱）。

## 2a · 竞品分层地图（对治「竞品忽视」）

创业者有个通病叫**竞品忽视**：太专注自己的愿景，系统性低估别人在干嘛。解药：**让 Claude 给每一层竞品做最强的「它会赢、你会输」论证**——不是一驳就倒的稻草人版本，而是最难反驳的那版。

分 4 层列出：
- **直接竞品**：做同样的事、抢同样的用户。
- **间接竞品**：解决同一个痛、但形态不同的——**尤其包括「用户现在的免费替代行为」**。这一条最容易漏，却常常是真正的对手（订阅那例里，真对手是「Apple 一键退订」和「信用卡拒付」，不是别的 App）。
- **潜在收购方 / 平台**：握着底层（操作系统、支付、流量）、随时能顺手把你做掉的巨头。
- **邻近玩家**：现在不在这赛道、但一抬脚就能跨进来的。

对每一层，逼出「它凭什么赢」：它的打法是不是其实更好？用户为什么选它？你以为的差异化，真护得住吗？

## 2b · 竞品评论 / 未解决抱怨（problem-solution fit）

**复用第 1 步 1d 的 opencli 肌肉，换个镜头**：1d 是为了反驳自己，这里是为了给竞争格局画像 + 找没被满足的需求。同一批真人原话，按「竞品」重新组织：

1. 用 opencli 搜竞品名 +「差评 / 不好用 / 退款 / 坑」（中文：小红书 / 知乎；英文：Reddit / HN / G2 / App Store 评论）。
2. 综合出 **top 未解决抱怨**：现有方案反复被骂、却一直没修的点。
3. 对账：**你的假设正好解决其中一两条吗？** 是 → 强 problem-solution fit 证据；不是 → 也是关键信息（你解决的可能不是用户最痛的）。

## 2c · TAM / SAM / SOM + 买家地图（最容易跳过、最不该跳过）

⚠️ 这是上一轮**整段被跳过、被审计点名的最大窟窿**。哪怕粗，也必须做，因为它回答生死问题：**到底有没有一个付得起钱、又足够大的人群。**

- **TAM（总市场）/ SAM（你能服务的）/ SOM（你现实能拿到的）**：用公开数据，**自上而下**（行业报告、市场规模）+ **自下而上**（人群数 × 渗透率 × 客单价）各估一遍。两个数对不上 → 假设里有问题。
  - ⚠️ 两个常见陷阱：①**别把「用户损失池 / 痛点总额」当 TAM**——「全美一年因闲置订阅浪费 $640 亿」是用户的损失，不是你能收的钱；你的 TAM 是「愿为这个解法付费的人 × 客单价」，两者可能差几个数量级。②**别把同名的 B2B 市场数字当你的 C 端市场**（如「订阅管理软件 $9B」其实是给商家收费的计费基建 Chargebee/Recurly，不是 C 端取消 App）。搜市场规模时务必核对这个数到底在算谁。
- **市场在扩张、整合、还是成熟？** 决定你的时机和差异化。（一堆同款 Show HN 0 评论 = 供给过剩 / 红海；一个免费巨头吃掉底层 = 成熟且天花板低。）
- **买家地图（关键）**：谁掏钱、谁拍板、谁使用——**是不是同一个人？**
  - 这里埋着想法的生死。我们最痛的发现是 **「需要它的人 ≠ 付钱的人」**：独立开发者需要但 0 预算不付费；电商 / 品牌付费但没这个痛。**当「需要的人」和「付钱的人」是两拨、且付钱那拨没这个痛——基本判结构性死刑。**
  - 所以必须逼问：在我锁定的人群里，**真正会掏钱的那个子集是谁、有多大？** 估不出来，就是 SOM ≈ 0 的危险信号。

注意：TAM/SAM/SOM 再漂亮也只是**桌面模型**，不是需求本身。它的作用是判断「值不值得继续 + 该聚焦哪个付费人群」，真实需求仍要第 3 步真人验证。

## 2d · 趋势分析（你是不是踩对了时间点）

- **3 个外部趋势**，跨 **法规 / 技术 / 人口** 三类，各判定**顺风还是逆风**、未来 ~2 年。（订阅那例：FTC 一键取消规则被撤 = 逆风；AI 让造产品变便宜 = 对「分发」是顺风、对「做工具」是逆风。）
- **类比市场**：别的市场解过同一个问题吗？抄它什么、避它什么。（我们用中文「种草 / 代运营」当类比，直接验证了「代做内容」这门生意的真实经济学和柠檬市场属性。）
- **用户语言**：复用第 1 步的频率扫描——用户描述这个问题 / 品类时高频用什么词？命中你的定位语言吗？品类词被污染了吗（「UGC」=廉价假货、「代运营」=割韭菜）？

## 2e · 收尾交接

产出：竞品 4 层图（含「它凭什么赢你」）+ top 未解决抱怨 + TAM/SAM/SOM 粗估 + 买家地图 + 3 趋势顺逆风。

最关键一句结论：**这个市场里，有没有一个会掏钱、够大、且你切得进去的人群？** 答不出「有、是谁」，就别进第 3 步之后的任何重投入。

并标注：以上仍是桌面研究（第 2 档证据），且会随你对问题的认知更新而变——**问题假设一动，回来重跑这一步。**

## → 2e 之后 · Step 2 收尾，跟用户说人话

Step 2 走完，给用户一段大白话总结：
1. **这是个什么样的市场**——挤不挤、是不是已经有人（尤其免费的）把位置占了。
2. **有没有人会掏钱、是谁**——正面回答这个生死问题，别绕弯。
3. **值不值得继续**——给一个明确倾向（继续／换方向／别做），并说清这还是桌面判断、最终要真人验证。

一句话概括最好：「**市场就这样：___；会掏钱的是 ___（或者：基本没有）；所以我建议 ___。**」

**然后停住，别自动进 Step 3。** 给用户三选一，等他拍板：
- ✅ 市场撑得住 → 进 Step 3，设计真人访谈
- ✏️ 要回去改假设 → 回 Step 1 / 2 重跑
- 🛑 市场判死 → **就此打住**

# 第 3 步：设计并跑客户访谈（桌面证据 → 真人第 1 档）

**目标**：把前两步攒下的「待真人验证」清单，拿去问真人。这是整套方法里**唯一能真正证伪你**的一步——前面再扎实也只是二手。

**前提**：Step 1 的承重假设 + 那个「访谈头号问题」+ Step 2 的买家裂缝。它们直接决定你问谁、问什么。

**⚠️ 这一步你在聊天框里做不完。** Claude 能帮你定画像、写提纲、审问题、复盘笔记；但**真人访谈得你自己去跑**——所以这步会在「提纲给你了」那里停一次，等你聊完带原话笔记回来，再做复盘。

产出：①精确的「找谁」画像 + 在哪找 + 先找谁；②一套 Mom-Test 提纲（只挖过去、不推销）；③你聊完之后的「支持 vs 反对」复盘 + 拍板。

## 3a · 找谁（精确画像 + 在哪 + 优先级）

- **精确到具体的人**：不是「独立开发者」，而是「过去 6 个月发布过 C 端产品、且卡在获客的中国出海个人开发者」。产品类型 / 资历 / 团队规模越具体越好。**唯一判据：他最近真的亲身经历过这个痛吗？** 没亲历的人给的是意见，不是证据。
- **在哪找**：复用 Step 1/2 发现的据点（例：独立开发者扎堆在 即刻 / 小红书出海话题 / Reddit r/SaaS / X build-in-public）。
- **先找谁**：按「离痛多近」排序，痛得最新鲜、最深的先聊。
- **怎么约**：在他们出没的地方直接私信，开场只说「想请教你上次发布的经历」，**别说你在做产品**。用一张简单的表跟进谁约了、聊没聊。
- **故意掺进反样本**（对抗确认偏误）：除了「踩了坑的人」，再找 1–2 个**成功了的**（看他靠的是不是你赌的那个原因——若成功者根本没靠它，你的根因假设就被削弱）和 1–2 个**最后发现是另一个原因、转型 / 放弃的**人。只找失败者、只找卡在你假设那一环的人，会把你直接推向你想听的答案。⚠️ 注意：属于「根因 C（其实没人要）」的人往往早就安静放弃、不发声，你几乎搜不到——得主动去「失败自白」帖里捞那个安静离场的人。
- ⚠️ **别又掉回音壁**：你要聊的是**真实目标用户 / 受苦者**，不是其他做产品的同行。同行给你共鸣，不给你真相。

## 3b · 问什么（Mom Test：只挖过去，不推销）

四条铁律（决定你拿到真相还是客套）：
1. **问过去的具体行为，不问对未来的假设。** ❌「你会用吗 / 愿意付费吗」→ 拿到的是想象和客套；✅「上次遇到这事是什么时候？你**具体做了**什么？」
2. **别推销、别提你的方案。** 一旦你说出想法，对方就开始照顾你的感受，数据当场变脏。理想情况：前几次访谈对方根本不知道你要做什么。
3. **挖真金白银和真实动作**：为这事花过钱吗？花在哪？现在还在用吗？折腾过哪些土办法？——**花过钱 / 花过力气，才是真痛的证据**；嘴上说「很烦」不是。
4. **顺着承重假设设计每一道题**：Step 1/2 的每条「待真人验证」，都要有一道过去式问题去戳它。尤其那个**互斥根因（X vs Y）**——裁决它的正确做法**不是**问「你觉得是因为 X 还是 Y」（当事人极不擅长归因自己为什么失败，你给的选项框还会诱导他往里选），而是**让他按时间顺序复述上次那件事的动作流水**（「你一步步做了什么，从打开哪个东西开始」），卡点会自己掉出来；**归类留给你事后做，别让受访者替自己做诊断。**

写完先让 Claude 审一遍，挑出 **引导性 / 指向未来 / 太宽泛 / 会引出「社交正确答案」** 的问题，并给最可能被打太极的 2–3 处设计追问（「能给我讲个具体例子吗」「那次后来怎么样了」）。

（多角色分开设计：掏钱的人和用的人若不是同一个，两套问法。）

→ **提纲定稿后停住。** 这不是 kill-gate，是真实世界接力：「去聊 **5–8 个**符合画像的人，把原话笔记带回来，我们再复盘。」Claude 替你跑不了这一步——这恰恰是它最值钱的地方。

## 3c · 访谈后复盘（防自我欺骗）

> **这是 Step 3 的下半场入口**：用户把真实访谈内容带回来，才从这里继续——3b 之前 Claude 不跑这一半，也不替你编访谈。笔记**不用工整、也不用凑满 5 个**：哪怕只有 3 段潦草的原话/数字也能开始，把你记下的原样贴回来即可（「每 5 个」是节奏，不是门槛）。**没有真人笔记，就没有这一步——没有桌面替代品**，这正是 Step 3 的意义。

笔记回来后：
- 每场先 debrief：**确认了什么 / 挑战了什么 / 什么让你意外**（意外的往往最值钱）。
- **每 5 个**，列两张表：支持假设的证据 vs 反对假设的证据，每条引用真人原话。
- ⚠️ 如果「支持」那栏明显更长，**先别高兴**——问一句：这是数据真这样，还是我在挑我想听的？（人天然把模糊回答往有利方向解读——这正是前面所有桌面步骤防不住、只有真人能戳破的偏差。）

## → 3c 之后 · Step 3 收尾，说人话 + 闸门

聊完真人，给用户一段大白话总结：
1. **真人到底证实了还是推翻了你的核心假设**——尤其那个根因 X/Y，和付费意愿。
2. **最意外的一条**是什么（常常是整个想法的转折点）。
3. **凭证强度**：是真有人为此花过钱 / 折腾过，还是只是嘴上认同？

一句话概括最好：「**聊完 N 个真人，___（问题 / 根因 / 付费意愿）被证实/证伪了，所以我建议 ___。**」

**然后停住，三选一，等用户拍板：**
- ✅ 核心假设被真人坐实 → 进 Step 4，设计方案
- ✏️ 部分被推翻 → 回 Step 1 改假设、重跑
- 🛑 核心被证伪 → **就此打住**——这是整套方法里**最有价值的一次「早死」**：你用几次聊天，省下了造一个没人要的产品。

# 第 4 步：设计方案概念（不是 MVP、不是原型、不是代码）

**目标**：基于 Step 3 的真人验证，设计出一个**经得起压力测试的方案概念** + 它押的承重假设。产出是纸面的——「方案该长什么样、靠哪几件事为真」，**不造任何东西**。
> 梯子：方案概念 → 轻量原型 → MVP。**本 skill 只到方案概念**；原型不做；MVP 是下一个阶段、另一个 skill。

**硬门槛**：Step 3 真的用真人验证过。**没有真人结论就别设计方案**——否则你在为一个没被证实的问题做一个漂亮设计。

## 4a · 现实检查点：还该不该设计？（先过这关）

回到 Step 3 的真人结论，三种情况：
- ✅ 真人坐实了问题 + 你的解法方向 → 继续 4b。
- ✏️ 真人证实了问题，但**根因 / 用户想要的解法变了**（订阅那例：根因是 A 遗忘、不是 B 摩擦；用户要「提醒」不要「自动取消」）→ 继续，但**你要设计的对象换成了「被验证出来的那个问题」**。
- 🛑 真人把核心前提证伪了 → **别设计，停。** 这里最容易犯的错就是闷头给方案——给一个没人要的问题配一个精致解法。

⚠️ 一条贯穿纪律：**设计要对着「验证揭示的问题」，不是「你出发时假设的问题」。** 这两个经常已经不是一回事。

## 4b · 先摆备选方案，别嫁给第一个

同一个被验证的问题，至少列 **3 种解法形态**（工具 / 人肉服务 / 数据·情报产品 / 嵌进别人的产品 / 内容或社区……）。别默认你出发时那个形态。把它和其它摆一起，按三条挑：**最对得上真人想要的 + 你真能做的 + 有没有壁垒**。

选出来的那个，说清：它具体是什么、给谁、解决真人验证出的哪个痛、为什么是这个形态而不是另外两个。

## 4c · 三个最承重的假设（假设 → 必须为真 → 失败后果）

找出方案**最依赖、最可能错**的 3 个假设（就 3 个，别凑成一堆泛泛的风险）。每个写成三段：
- **假设**：……
- **要它成立，必须为真的条件**：……（可证伪、最好能再去验）
- **如果它不成立**：方案是整崩，还是只是收窄？

按「哪个最决定生死」排序。

⚠️ 最后一查：你的方案是**拆掉了**前面发现的那堵墙，还是只是**把它挪了个位置**？（订阅那例：换个形态但「漏钱者≠付费者」还在 = 只是挪墙。）**只挪墙，不算解决。**

## → 4c 之后 · Step 4 收尾，说人话 + 闸门（本 skill 终点）

大白话总结：基于真人，你最终的方案是什么、押哪几件事、最脆的是哪一件。

一句话最好：「**方案是 ___，它成立全靠 ___ 为真；这件事我已经验证 / 还没真正验证。**」

然后停，三选一：
- ✅ 方案概念站得住、承重假设有真人支撑 → **本 skill 到此为止。** 想法阶段验证完成，下一步进 **MVP 阶段**（另一个 skill / 另一个阶段）——问题从「值不值得做」变成「先做哪一块」。
- ✏️ 发现某个承重假设其实没真人验证过 → 回 Step 3 补访谈。
- 🛑 现实检查点就没过（真人把前提证伪）→ 打住，别设计。
